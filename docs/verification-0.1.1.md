## Подписанное обновление и runtime

Именно подписанный release APK0.1.0 установлен на нашем одноразовом `AtlasApi36` / `emulator-5554`. Через UI создана синтетическая поездка France с заметкой `Atlas upgrade verification`; она сохраняется после force-stop. Поверх установлен **release0.1.1** с тем же applicationId и ключом, без удаления данных. VersionCode2 / versionName0.1.1 подтверждены. Поездка и заметка сохранились.

Первое открытие после обновления показывает disclaimer. Back его не закрывает. После явного подтверждения и force-stop/relaunch он не появляется. Повторная runtime-проверка подтверждает сохранность журнала и принятого предупреждения. Локальный отчёт: `build/release-runtime-v2/report.json`.

На том же подписанном0.1.1 APK проверены встроенное RU→HK14 и Settings со всеми четырьмя источниками. Явное сетевое обновление действительно загрузило оба feed: community `2026-10-26T07:52:31.054792Z`, HK CSV `2026-10-26T07:52:34.256599Z`. После force-stop/cold start обе метки, четыре источника, HKsourceAsAt2025-12-31 и RU→HK14 сохранились. В Settings нет ошибки обновления. Синтетическая поездка удалена через UI; журнал пуст после повторного старта. Итог smoke: **PASS**.

Тестовая UI-автоматизация отдельно исправлена: dumpsys IME содержит исторические флаги, которые нельзя считать текущей видимостью клавиатуры; название CLDR — Hong Kong SAR China. Эти прерывания сценария не потребовали изменений production APK. Полный финальный smoke выполнен на APK с хешем ниже.
